# WH3 Core changelog

Release entries are generated by Sampo from `.sampo/changesets` when preparing a release PR.

## 0.3.1 — 2026-10-02

### Fixed

- [784a71b](https://github.com/Mnwa/WH3-Mod-Manager/commit/784a71b02b271912f2487251fe20bf012870fa60) Fix the problem-mod search naming half of a large mod list: mods linked through a shared framework or overhaul are now tested separately, each with the mods it requires. "Restore without it" also switches off the mods that require the culprit, and the search keeps track of mods when Workshop updates rescan the library mid-search.

## 0.3.0 — 2026-10-02

### Fixed

- [adb152b](https://github.com/Mnwa/WH3-Mod-Manager/commit/adb152b535183d12240bff696353f3067357c416) Import the original manager's load order correctly: its presets are now ordered the way
  it launches them (name order with pinned positions) instead of by list position. Hidden
  and always-enabled mods and the game start options are imported as well.
- [07fed91](https://github.com/Mnwa/WH3-Mod-Manager/commit/07fed91e793c3d7cb3045c68de2a8eed0b528c90) Keep automatic mod and save updates working when watched folders use symbolic links,
  including macOS paths under `/var`. Folders whose real path cannot be resolved, such as
  some RAM, network or virtual drives on Windows, are still watched by their configured path.
- [adb152b](https://github.com/Mnwa/WH3-Mod-Manager/commit/adb152b535183d12240bff696353f3067357c416) Fix a crash when a rescan or a new game folder produced fewer mods than before, and use
  native path separators for the Workshop folder written into the game's mod list.

### Added

- [adb152b](https://github.com/Mnwa/WH3-Mod-Manager/commit/adb152b535183d12240bff696353f3067357c416) Add Steam Workshop integration: titles, authors, tags, requirements and update times are
  refreshed from Steam; mods can be updated, re-downloaded, subscribed and unsubscribed
  (with confirmation) from the list; missing requirements can be installed and are enabled
  once downloaded; Steam collections can be imported as presets. Steam calls run in a
  short-lived worker process so the manager never appears to Steam as the running game.
  Release archives now include `steam_api64.dll`.
- [fd19d47](https://github.com/Mnwa/WH3-Mod-Manager/commit/fd19d47a6b80d4f68d01a9df3597b7f06ec27e64) Follow the disk and the game like the original manager: the mod list refreshes by
  itself when Steam adds, updates or removes mods, new saves appear in Continue, and a
  running game is detected (Play queues a relaunch for when it closes, and the game can
  be closed from the manager). Add the original's shareable mod-list text, a guided
  search for the mod that causes a problem, and "Reinstall from Workshop" for broken
  downloads.
- [adb152b](https://github.com/Mnwa/WH3-Mod-Manager/commit/adb152b535183d12240bff696353f3067357c416) Check GitHub Releases for a newer version on start (published Windows builds) or from
  Options, download the executable, verify it against the release's `SHA256SUMS.txt`,
  replace the running binary and restart after saving the library.
- [adb152b](https://github.com/Mnwa/WH3-Mod-Manager/commit/adb152b535183d12240bff696353f3067357c416) Add the original game start options (skip intro movies, script logging, auto-start
  custom battle, make units generals) and "Close manager on Play", a Continue button that loads the newest
  campaign save, a saves menu that loads a save or enables the mods recorded in it, and
  the automatic "On Last Game Launch" preset. Presets can now also be merged into or
  subtracted from the current list, replaced and deleted.
- [adb152b](https://github.com/Mnwa/WH3-Mod-Manager/commit/adb152b535183d12240bff696353f3067357c416) Add load-order rules like the original manager: "load before/after" rules from the row
  menu, rules shipped by mods in `whmm\load_order.whmm` (each can be switched off), and
  pinned positions for mods moved by hand. Rules are applied after changes and before
  every launch, and the original's rules are imported from its configuration.
- [adb152b](https://github.com/Mnwa/WH3-Mod-Manager/commit/adb152b535183d12240bff696353f3067357c416) Replace the overlap list with a compatibility check that reports overwritten files with
  the winning mod, colliding DB row keys with the
  winning row (parsed with the bundled WH3 schema, including compressed packs), missing pack dependencies and Steam
  requirements, and conflicting start positions, with per-row badges. Workshop mods older than
  the last game update that overwrite vanilla DB or Lua files are marked as possibly outdated.
- [fd19d47](https://github.com/Mnwa/WH3-Mod-Manager/commit/fd19d47a6b80d4f68d01a9df3597b7f06ec27e64) Add the original manager's remaining mod-list and launch options: a two-list layout
  (not enabled | enabled in load order), category groups, row sizes, resizable columns,
  Workshop mod staging in the game folder with cleanup after exit, copying or linking
  mods into the game's data folder, raising the game's process priority, and waiting for
  changing mod files before a launch. Interface preferences now use the WHP2 record and
  the library is saved as WHM4; older files are migrated.
- [adb152b](https://github.com/Mnwa/WH3-Mod-Manager/commit/adb152b535183d12240bff696353f3067357c416) Bring the mod list closer to the original manager: drag rows to change the load order
  (plus Top/Bottom and Alt+Home/End), sort by order, enabled state, title, pack, author,
  update time or size without changing the launch order, an always-visible scrollbar,
  mod thumbnails, author and "updated" columns, and a right-click menu with Workshop and
  Steam links, Show in folder, copy path/name, categories, Keep always enabled and Hide.
  Several mods can be selected with Ctrl/Shift+click or Ctrl+A and enabled, moved or hidden
  together. Hidden mods have their own filter, categories can be edited and used as a filter, and
  search accepts `/regex/`.

### Changed

- [adb152b](https://github.com/Mnwa/WH3-Mod-Manager/commit/adb152b535183d12240bff696353f3067357c416) Update GPUI Kit to 0.7 and use mimalloc as the GUI's allocator. The library file moves
  to the WHM3 format to store hidden and always-enabled mods, start options and load-order
  rules; WHM1 libraries are migrated on the next save and the previous file is kept as the backup.
  `WH3MM_HOME` selects a different data folder, for example for a portable copy.
- [fd19d47](https://github.com/Mnwa/WH3-Mod-Manager/commit/fd19d47a6b80d4f68d01a9df3597b7f06ec27e64) Redesign the interface so it can be used without a guide: a first-start screen, plain
  labels and explanations, a bar under the list that shows how to use it or the selected
  mod's actions, empty states with a next step and a sorted-view notice. The language is
  now an EN/RU switch, and the first start follows the Windows display language. Play
  saves the mod list before launching. The executable has its own icon and version
  information.

## 0.2.0 — 2026-10-02

### Added

- [34d8de6](https://github.com/Mnwa/WH3-Mod-Manager/commit/34d8de67eca4dbbb80f6f50e8bd7aa0195f73b38) Add the native WH3 mod-management core: Steam/Data/Workshop scanning, Unicode search,
  preset import/export and load order, PFH4/PFH5 index inspection, file-overlap reports,
  and a separate Windows game launch script. Import saved original-manager metadata
  and export it through the standalone `wh3-meta` CLI. Store libraries in the validated,
  versioned WHM1 binary format with atomic saves and a previous-generation backup.
